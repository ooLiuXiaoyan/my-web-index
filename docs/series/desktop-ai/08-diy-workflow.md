# 搭建自己的桌面工作流：从用产品到造流程

<span class="badge badge-done">已发布</span>

系列收官篇。前面七篇都在讲「选产品、用产品」，这篇回答进阶玩家的问题：**当通用产品触到天花板，怎么搭一套属于自己的桌面自动化工作流？**

## 为什么最终要走向自建

三个现实：

1. **通用产品的天花板**：商业产品服务的是最大公约数场景，你的独特流程（特定数据源 + 特定格式 + 特定交付渠道）永远差最后一公里
2. **厂商锁定**：工作流建在单一产品里，它改功能、调价、关停，你就得跟着搬
3. **能力可迁移性正在变好**：MCP 协议普及、技能包跨产品兼容（OpenClaw ↔ WorkBuddy），自建的积木越来越标准化，搭一次多处可用

## 积木一：定时任务

工作流的发动机。三条路线各有位置：

| 路线 | 工具 | 适合 |
| --- | --- | --- |
| AI 产品内置 | 豆包定时任务、WorkBuddy、Kimi Work | 非技术用户、轻量任务 |
| 系统级 | Windows 任务计划、cron | 稳定的后台脚本 |
| CI/CD | GitHub Actions 定时工作流 | 有仓库依托的内容/数据任务 |

别小看第三条：本站 [AI 厂商图谱](../ai-vendors/)系列的维护就是真实案例——一个 GitHub Actions 工作流每 3 天自动创建「信息更新提醒」Issue，零成本、有日志、永不忘事。**不是所有定时任务都需要 AI，可靠优先。**

## 积木二：技能与技能包

技能 = 把「一类任务的做法」固化成可复用的指令包。2026 年的好消息是技能开始跨平台流动：

- OpenClaw 的技能包可以直接迁移到 WorkBuddy，反之亦然
- 自己编写技能的门槛很低：本质上就是一份结构化的操作说明 + 少量脚本

建议从「每周重复三次以上的任务」里挑第一个技能：把做这件事的步骤、注意事项、输出格式写成技能，让 Agent 按它执行，再根据结果迭代。

## 积木三：MCP 连接一切

技能解决「怎么做」，MCP 解决「连到哪」（详见本站 [MCP 详解](../mcp/01-mcp-detail)）：

- 官方/社区已有大量现成 MCP 服务：文件系统、数据库、浏览器、各类 SaaS
- 私有系统（公司内部平台、自建服务）可以自己包一层 MCP，让任何兼容 Agent 直接调用

工作流的架构思路随之清晰：**Agent（大脑）+ MCP（连接）+ 技能（方法）+ 定时任务（节奏）**，四者拼出你的个人自动化。

## 实战：三个完整工作流示例

### 示例一：每日信息简报

```
07:50 定时触发
  → 浏览器 MCP 抓取 5 个信息源（行业资讯、GitHub Trending、指定博客）
  → Agent 按「简报技能」筛选、摘要、按模板排版
  → 生成 Markdown 存到本地目录 + 推送到微信/飞书
```

### 示例二：博客内容更新流水线（本站真实流程）

```
每 3 天 GitHub Actions 定时触发
  → 创建「AI 厂商信息更新」提醒 Issue（清单式待办）
  → 人工/Agent 按 Issue 更新 docs/series/ai-vendors/ 下的文章
  → git push 触发 Pages 工作流：VitePress 构建 → 部署上线
```

这个流程的精髓是**机器负责不忘事，人负责把关质量**——定时提醒自动化，内容更新人工确认后再发布。

### 示例三：本地智能体组合

进阶玩法：用 [OpenClaw](../openclaw/) 或 [Hermes](../hermes/) 这类开源框架做本地 Agent 运行时，自己接模型（多家 API 可切换），用 MCP 挂私有数据源，技能全部自己掌控。成本是要维护，收益是完全自主——适合有开发能力、对数据和灵活性都有要求的玩家。

## 系列总结与展望

八篇走完，回顾一下这条线：

1. **形态**：对话 → 辅助 → 执行，2026 年跨过分水岭
2. **产品**：没有全能冠军，只有场景最优
3. **能力**：文件、浏览器、定时、Office 四大件
4. **实测**：规则明确的任务已可靠，开放任务仍需人兜底
5. **案例**：WorkBuddy 证明入口与上下文是下半场
6. **原理**：接口优先，视觉兜底
7. **安全**：把 Agent 当能力很强但没有常识的实习生
8. **自建**：Agent + MCP + 技能 + 定时，拼出你的工作流

最后一个判断留给未来：**桌面 Agent 的终局可能不是某个产品，而是「操作系统的 AI 层」**——当系统级 API 向 Agent 全面开放，今天这些产品的形态还会再变一次。本系列会跟着这个领域继续更新，欢迎收藏，常回来看看。
