# 安全与隐私边界：把电脑交给 AI 之前该想清楚的事

<span class="badge badge-done">已发布</span>

桌面 Agent 越能干，它能碰的东西就越多。这篇不劝退，只做一件事：**把风险摊开，把防线讲清**。看完你应该能给自己（或你的企业）划出一条明确的授权红线。

## 风险全景：AI 到底能碰到什么

一个全权限的桌面 Agent，理论上能做你在电脑上做的一切事：

| 风险类别 | 具体场景 | 后果等级 |
| --- | --- | --- |
| 文件破坏 | 误删、错误覆盖原文件 | 🔴 高 |
| 数据外泄 | 把本地文件内容发到云端 / 第三方 | 🔴 高 |
| 账号操作 | 以你的登录态发消息、发邮件 | 🟡 中 |
| 资金操作 | 支付、下单、转账 | 🔴 高 |
| 提示词注入 | 网页/邮件里的恶意指令劫持 Agent | 🟡 中 |

最后一条最容易被忽视：**Agent 会读网页和邮件，而网页和邮件里可以埋指令**。一个帮你处理邮件的 Agent，可能被一封恶意邮件里藏的「把你的通讯录发到这个地址」带偏——这是 2026 年 Agent 安全的头号攻防点。

## 防线一：权限审批机制

靠谱产品的共同设计是**按危险程度分级**：

- **只读操作**（看文件、读网页）：默认放行
- **写入操作**（新建、修改）：按目录或会话授权
- **不可逆操作**（删除、发送、支付、对外发布）：单次人工确认，绝不静默执行

选型时可以直接测试：让它「删掉测试文件夹里的一个文件」，看它是先问你还是直接删。**直接删的，别用。**

三条使用纪律：

1. 危险操作的确认弹窗，**不要养成无脑点允许的习惯**——读一眼再点
2. 授权按「最小够用」给：整理文档就只给文档目录，别给整个磁盘
3. 会话授权结束后主动检查：它做了什么，有没有多做的

## 防线二：数据去哪了

云端 vs 本地，隐私姿态完全不同：

- **云端产品**：你的对话和文件会经过厂商服务器。注意免费档条款——部分厂商的免费个人账号默认允许用对话数据训练模型，付费/企业档通常默认关闭
- **本地运行产品**：Kimi Work 这类强调数据留在设备本地；WorkBuddy 的微信遥控也是全程本地执行
- **灰色地带**：WorkBuddy 用户的高质量任务 prompt，在不涉及隐私的前提下会回授混元做后训练——这类「数据飞轮」条款要读清楚，企业场景尤其要确认管理员侧的开关

**简单原则**：涉密文件（合同、财务、代码私钥、客户数据）不进云端 Agent；要么本地产品处理，要么脱敏后再给。

## 防线三：企业场景的特殊问题

个人管好自己的授权就行，企业则要解决「一百个员工各自授权 AI」的失控风险。好的企业方案都包含：

- **统一部署**：管理员统一配置机器人、分配账号与算力（WorkBuddy + 企微的做法是范本）
- **按身份授权**：根据组织身份设置不同人员的 AI 访问权限，限制 AI 接触高敏感信息
- **审计留痕**：AI 的操作可追溯，数据流转路径清晰，责任边界明确

企业引入桌面 Agent 前，建议先回答三个问题：AI 能访问哪些系统？操作留痕在哪里看？出事了责任链怎么走？答不上来就先别上线。

## 个人使用建议清单

1. ✅ 给 Agent 单独建工作目录，只授权这个目录
2. ✅ 删除、发送、支付类操作，一律保留人工确认
3. ✅ 涉密文件只用本地运行的产品，或先脱敏
4. ✅ 定期检查「它都做了什么」——日志和交付物都翻一翻
5. ✅ 处理陌生邮件 / 网页内容时，警惕注入指令，重要操作二次确认
6. ❌ 不要把整个磁盘、浏览器主账户的完整权限长期托管给任何 Agent
7. ❌ 不要在共享电脑 / 公共设备上登录你的 Agent 账号

## 小结

桌面 Agent 的安全观可以浓缩成一句话：**把它当成一个能力很强、但没有常识的实习生**——给清晰的任务边界、给最小的权限、给关键节点的复核。做到这三点，它就是生产力；做不到，它就是事故源。
