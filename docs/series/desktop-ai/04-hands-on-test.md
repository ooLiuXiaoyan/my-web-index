# 同一任务实测：不看广告看疗效

<span class="badge badge-done">已发布</span> <span class="badge badge-wip">持续补测</span>

> 📋 **方法说明**：本篇汇总各产品的公开实测记录（来源均为可查证的媒体报道与官方资料），并给出可复现的测试框架。标注 🔬 的任务建议你在自己的环境复测——你的文件、你的软件、你的网络，才是最准的尺子。

## 测试方法

### 任务设计原则

好的测试任务满足两个条件（这也是判断 Agent 是否适合某任务的通用标准）：

1. **一段话能讲清**：如果需要开个会才能解释明白，现阶段任何 Agent 都做不好
2. **有明确的「完成」标准**：「桌面截图按月归档完毕，无遗漏」可验证；「把房间收拾得舒服点」不可验证

### 参评对象与环境

- 参评：ChatGPT Work、Claude Cowork、Kimi Work、豆包电脑版、WorkBuddy
- 统一标准：同一任务描述原文喂给各家，记录完成度、耗时、人工介入次数

## 任务一：文件整理归档 🔬

> 「把桌面上这个文件夹里的截图，按拍摄月份归档到 2026-01 至 2026-11 的子文件夹，完成后给我一份清单。」

**考察点**：本地文件读写、多步骤执行、结果汇报。

公开实测记录：

- **WorkBuddy**：媒体测评中按一句话整理散乱文件夹成功，过程可视，结果本地交付
- **豆包工作任务模式**：官方演示即「整理桌面上的图片并按月份归档」，授权后分步执行并汇报
- **Claude Cowork**：文件类任务是其主场，工作目录内操作稳定

**经验**：这类「规则明确、无需联网」的任务成功率最高，是当前所有执行型 Agent 的舒适区。翻车点多在**边界情况**：重名文件、无日期的文件如何处理，任务描述里最好提前说清。

## 任务二：资料调研出报告

> 「分析这 10 份经营数据 Excel，找出买家满意点和吐槽集中的问题，生成一份带图表的分析报告。」

**考察点**：多文件理解、数据分析、成品质量。

公开实测记录（来自财新周刊封面报道《抢占办公室》等）：

- **WorkBuddy**：上传十多份 Excel 经营数据，几分钟完成分析并生成可视化数据管理仪表盘，可以网页形式操作、分享
- **豆包工作**：自动整理商品评论区，输出产品分析报告，并进一步生成广告图与多语种文案
- **Kimi Work**：多份 PDF 与长文档阅读 + Agent 集群并行调研；在 SuperCLUE 2026 年 10 月 Office Agent 测评中，数据分析与材料撰写两个维度领先

**经验**：这是各家差距最大的战场。报告「能生成」和「能直接用」之间隔着事实核查——**Agent 集群并行产出的引用与数字，必须人工核对后再外发**。

## 任务三：定时写周报

> 「每周五下午 5 点，汇总本周工作文件夹里的文档变更，生成周报初稿。」

**考察点**：定时任务、长周期可靠性、交付方式。

公开实测记录：

- **WorkBuddy**：2026 年 3 月版本即支持后台自动化任务，每日自动生成日报、周报；结果可推送到微信
- **豆包电脑版**：定时任务为电脑版独占功能，网页版不可用
- **Kimi Work**：定时任务 + 本地执行，数据不出设备

**经验**：定时任务的真实瓶颈不是「能不能跑」，而是**电脑关没关**。所有本地 Agent 都依赖设备在线；真要无人值守，要么保证开机，要么选云端方案。

## 实测结论

| 任务类型 | 成功率 | 关键变量 |
| --- | --- | --- |
| 规则明确的文件操作 | ★★★★★ | 边界情况要在任务里说清 |
| 多文档分析出报告 | ★★★☆☆ | 事实核查必须人工兜底 |
| 定时例行任务 | ★★★★☆ | 设备在线是前提 |

三条普适结论：

1. **Agent 擅长一段话能讲清的任务，不擅长需要开会解释的任务**——任务拆分是你的工作，不是它的
2. **验证码、支付、删除，靠谱的产品都会停下来问你**——不停下来问你的，反而要警惕
3. **第 1 次成功不代表第 100 次成功**——界面改版、弹窗干扰都会让昨天的流程今天翻车，定期复查自动化流程
