# 从聊天框到桌面 Agent：AI 办公助手的三次形态跃迁

<span class="badge badge-done">已发布</span> <span class="badge badge-wip">持续更新</span>

这是「AI 桌面办公助手」系列的开篇。在逐一评测产品之前，先回答一个更根本的问题：**桌面 AI 助手这个品类，到底进化到哪一步了？** 看清这条「对话问答 → 系统级辅助 → 自主执行」的演进主线，后面的横评和实测就有了统一的标尺。

## 一个分水岭问题

判断一个 AI 助手属于哪个时代，只需要问一句：

> **「它能不能帮我把桌面上的 100 张截图，按月份归档到对应文件夹？」**

- 如果它给你一段「你可以这样做」的文字教程——它还是个**顾问**；
- 如果它直接动手把文件归好档、把结果汇报给你——它才是个**同事**。

从顾问到同事，就是这三年的故事。

## 第一次跃迁：对话问答（2022–2024）

ChatGPT 网页版开启的时代。AI 助手住在浏览器的一个标签页里，工作方式只有四个字：**复制粘贴**。

- 写周报：把零散记录粘进对话框，把生成的周报粘回文档
- 读资料：手动上传 PDF，把摘要抄走
- 国内同期：文心一言、通义千问、Kimi、豆包，初期都是纯网页对话形态

**能力边界**：输出永远停留在对话窗口里。AI 很会说，但一切落地动作都要人来做。这个阶段的 AI 助手本质上是一个「随叫随到的顾问」，效率提升取决于你搬运信息的手速。

## 第二次跃迁：系统级辅助（2024–2025）

AI 开始从浏览器里「长」到操作系统上，标志性能力是三个：

- **全局快捷键唤起**：在任何应用里一键呼出 AI（Gemini 桌面端用 Alt + Space，Microsoft Copilot 直接进了 Windows 任务栏）
- **划词交互**：选中任意文本，即时翻译 / 解释 / 总结（豆包电脑版的划词、各类划词插件）
- **悬浮球常驻**：不打断当前工作流，随用随走

**能力边界**：AI 贴近了系统，但**只读不写**。它能看见你选中的文字、你贴给它的内容，却不能碰你的文件、不能替你操作软件。本质上还是一个「坐在你旁边的顾问」——离得近了，手还是没伸出来。

## 第三次跃迁：自主执行（2025–2026）

真正的分水岭：**AI 开始动手了**。三个标志性能力在这一阶段集齐：

| 能力 | 含义 | 代表 |
| --- | --- | --- |
| 本地文件读写 | 直接整理、生成、修改你电脑上的文件 | Claude Cowork、Kimi Work、豆包工作任务模式 |
| Computer Use | 截屏理解界面，模拟鼠标键盘操作软件 | Claude computer use、混元 Hy4、ChatGPT 桌面端 |
| 定时任务 | 设定计划，到点自动执行并交付结果 | 豆包定时任务、WorkBuddy、Kimi Work 定时任务 |

交付物随之改变：从「一段回答」变成「一份文件」「一次完成的家务」。2026 年 10 月腾讯 WorkBuddy 与企业微信双向联合、豆包电脑版上线工作任务模式，标志着国内厂商也全面跨过了这条线。

## 为什么分水岭出现在 2026

三个条件在这一年同时成熟：

1. **工具调用标准化**：MCP 等协议普及（见本站的 [MCP 详解](../mcp/01-mcp-detail)），模型调用外部工具从「各家私有玩法」变成「通用语言」，技能包可以跨产品迁移（WorkBuddy 直接兼容 [OpenClaw](../openclaw/) 技能就是例证）
2. **Computer Use 走出实验室**：新一代模型原生支持电脑操作，混元 Hy4 这类模型把幻觉率压到个位数，可靠性终于摸到可用的门槛
3. **落地场景被找到**：办公。IM 生态（微信 / 企微 / 飞书 / 钉钉）天然带着工作上下文和分发渠道，成为桌面 Agent 最好的入口

## 三种形态一图速览

| 维度 | ① 对话问答 | ② 系统级辅助 | ③ 自主执行 |
| --- | --- | --- | --- |
| 时代 | 2022–2024 | 2024–2025 | 2025–2026 |
| 形态 | 浏览器标签页 | 桌面客户端、快捷键、悬浮球 | 桌面 Agent |
| 与系统的关系 | 隔离 | 只读 | 读写 + 操作 |
| 交付物 | 一段文字 | 一段更顺手的文字 | 文件、报告、完成的任务 |
| 角色 | 顾问 | 坐在旁边的顾问 | 同事 |
| 代表 | ChatGPT 网页版、Kimi 网页版 | Copilot 任务栏、豆包划词 | Kimi Work、Claude Cowork、豆包工作任务模式、WorkBuddy |

> ⚠️ 注意：三种形态不是替代关系，而是并存关系。今天的大部分产品同时具备「对话」和「执行」两种模式，区别只在于执行能力的深浅——这正是下一篇横评要比的东西。
