# 横评与选型：2026 知识库平台全景

<span class="badge badge-done">已发布</span> <span class="badge badge-wip">定期刷新</span>

> 📅 数据截至 2026 年 11 月。产品迭代快，价格与配额以各官网为准。

三个主角都写完了，这篇收拢成一张选型地图：先正面对比 ima / Coze / Dify，再扩展视野看看其他值得知道的玩家，最后给出场景化决策路径。

## 主角三家正面对比

| 维度 | 腾讯 ima | 字节 Coze 扣子 | Dify |
| --- | --- | --- | --- |
| 一句话定位 | 个人知识伙伴 | 知识型 Bot 流水线 | 企业级 RAG 应用平台 |
| 知识库角色 | 个人资产 + 广场流通 | Bot 的配件 | AI 应用的地基 |
| 部署 | 云端 SaaS | 云端 SaaS | 开源自托管 / 云版 |
| 检索可控性 | 不可控（黑盒好用） | 少量配置 | 全链路可调 |
| 杀手锏 | 微信生态 + copilot 执行 | 分发渠道一键发布 | 私有化 + 工作流编排 |
| 数据敏感度容忍 | 低（云） | 低（云） | 高（可全离线） |
| 适合人群 | 个人/小团队 | 业务团队/运营 | 技术团队/企业 |

## 扩展视野：其他值得知道的玩家

### RAGFlow：文档解析最强

开源（8 万+ Star），主打**深度文档理解**：语义分块而非字符切割、可视化分片、表格与扫描件识别能力突出、混合检索 + 引用溯源。如果你的知识库以合同、报表、复杂 PDF 为主，Dify 解析吃力的部分它正好补上。短板：复杂 Agent 编排弱于 Dify。

### WeKnora：腾讯开源的新变量

微信团队开源（MIT），三个能力合一：RAG 问答 + ReAct Agent + **Wiki Mode**（自动从原始资料提炼实体关系、生成互链的 Markdown Wiki 和知识图谱）。两个亮点别处少见：**切片可直接编辑**（表格切错了不用重传整份文档）、提供 MCP Server 可作为其他 Agent 的统一知识层。

### FastGPT / MaxKB：国内老牌与业务友好型

FastGPT 是老牌开源 RAG，知识库问答成熟、提示词模板丰富；MaxKB 面向业务人员，开箱体验好、权限完善、深度定制弱于 Dify。两者都是「快速搭内部问答」的务实选择。

### Obsidian + 本地模型：个人离线组合

个人深度知识管理的另一条路：Obsidian 双链笔记做生产，积累到一定量同步进 Dify 或本地向量库做检索。内容生产与 AI 检索分离，数据全在自己手里（联动 [第 02 篇](./02-my-practice) 的个人实践）。

### 飞书知识库：协作沉淀型

如果团队已经在飞书里，它就是最省事的知识生产层——多人协作、权限细致。注意它的角色是「人写给人看」，喂给 AI 还是要走 RAG 平台。

## 场景选型矩阵

| 你是谁 / 要什么 | 首选 | 备选 |
| --- | --- | --- |
| 个人知识管理，微信素材多 | ima | Obsidian 组合 |
| 业务团队搭客服 Bot 快上线 | Coze | MaxKB |
| 技术团队，要私有化与可控 | Dify | FastGPT |
| 复杂文档（合同/表格/扫描件） | RAGFlow | Dify + 解析插件 |
| 涉密内网，全离线 | Dify + Ollama | 自建管线（见 [第 02 篇](./02-my-practice)） |
| 垂直行业非标数据（GIS、图纸） | 自建管线 | Dify + 自定义扩展 |
| 团队已在飞书，先要协作沉淀 | 飞书知识库 | + Dify 做 AI 检索层 |

## 决策树

```
数据能出本地吗？
├─ 不能 → Dify 私有化 / 自建管线（涉密场景见第 02 篇）
└─ 能 ↓
    主要诉求是？
    ├─ 个人用、要省心 → ima
    ├─ Bot 要快速上线到渠道 → Coze
    ├─ 嵌入业务流程、长期运营 → Dify（云版起步）
    └─ 文档解析质量优先 → RAGFlow
```

## 常见选型误区

1. **Wiki 与 RAG 库混为一谈**：「员工写文档」和「AI 读文档」是两层，选一层的产品补另一层的洞最痛苦
2. **按功能列表选，不按数据敏感度选**：涉密单位在 SaaS 上试错是纯浪费（我的教训，见第 02 篇）
3. **低估知识治理成本**：平台只占 20% 工作量，80% 在文档清洗、更新、权限——下一篇专讲
4. **一步到位幻想**：先用免费/SaaS 验证场景，再决定私有化投入，别反过来

## 小结

2026 年的知识库平台没有全能冠军，但分工已经很清晰：**入口看 ima，速度看 Coze，工程看 Dify，解析看 RAGFlow，底线场景看私有化与自建**。最后一篇解决所有平台都绕不开的问题：知识库的质量工程。
