# Dify 深度：可私有化的企业级 RAG

<span class="badge badge-done">已发布</span> <span class="badge badge-wip">定期刷新</span>

> 📅 信息截至 2026 年 11 月。GitHub `langgenius/dify`，14 万+ Star，开源（自托管免费），云版 Free / Pro $59 / Team $159。

Dify 是这个系列里唯一的开源选手，也是「知识库作为工程问题」的标准答案。官方披露其运行在全球超 140 万台设备、175 个国家，2026 年入选 Gartner AI Agent 管理平台魔力象限，客户包括 Anker、诺华、沃尔沃。我自己在涉密内网用它搭过团队知识库（见 [第 02 篇实战](./02-my-practice)），这篇把它的能力体系讲透。

## 产品定位：先想清楚一个词

Dify 不是传统 Wiki，它是**让 AI 读取企业知识的平台**：

- 它解决「AI 怎样使用企业知识」，不解决「员工怎样管理知识」
- 合理的企业架构是两层：**Wiki/KMS 负责知识生产与治理，Dify 负责 AI 检索与应用**

冲着「替代员工写文档的 Wiki」来用 Dify，会失望；冲着「给 AI 应用造检索底座」来用，它是最顺手的开源选择。

## 知识库流水线

完整链路：**接入 → 切分 → Embedding → 索引 → 检索**，每个环节都可调：

- **接入**：文档批量上传，v0.7+ 支持图片 OCR；表格类建议先转 Markdown 再传，效果远好于直接传 Excel
- **切分**：自动分块 + 自定义分段规则
- **检索**：混合检索、多路召回、Rerank 重排、引用溯源、多知识库联合检索——这几个开关是专业级与非专业级产品的分水岭
- **向量库**：默认 Weaviate 可存百万级向量；企业级推荐换 Qdrant（Rust 实现，性能更强）

## 工作流与 Agent：知识库的「用法」比「存法」重要

Dify 的差异化不在库本身，而在**知识检索可以作为一个节点嵌入任何业务流程**：

- Chatflow / Workflow 可视化编排：条件分支、代码节点、变量传递、多模型串联
- 在检索与生成之间插入「反思」「校验」节点，是工程上压幻觉的有效手段
- Agent 引擎（ReAct / Function Calling）可挂外部工具
- **API 发布**：一键把知识库应用发布为 REST API，对接 OA、业务系统、小程序——我的内网项目里这是最有价值的一项（见 [第 02 篇](./02-my-practice) 的六个升级点）

## 私有化部署

```bash
# Docker Compose 一键部署（官方标准姿势）
git clone https://github.com/langgenius/dify.git
cd dify/docker
docker compose up -d
```

要点：

- **模型接入**：数百种主流模型 + Ollama 本地模型（DeepSeek、Qwen 等），敏感场景可全离线（我的配置：Ollama + DeepSeek-R1 7B + nomic-embed，8GB 显存可跑）
- **企业能力**：RBAC 权限、SSO、全链路日志审计
- **成本账**：自托管免费但要付运维；云版 Free 是 sandbox（200 消息额度、50 文档），只适合体验

## 生产级优化：过了 demo 阶段该做什么

从 PoC 到生产，三个动作收益最大：

1. **知识库分层**：FAQ 库（精确匹配）+ 手册库（精细分块 + 混合检索）+ 案例库（按时间归档），配查询路由规则——「怎么/如何」先查 FAQ，含产品名查手册，其余全库
2. **未命中查询分析**：每周复盘「用户问了但 AI 答不出」的问题，反哺知识库补内容——这是知识库最常用的持续优化机制
3. **检索参数调优**：海量文档场景下默认参数不够用，Top-K、重排阈值、混合检索权重都要按业务测

## 已知短板（官方与社区共识）

- 面向通用场景，大型企业复杂权限、大规模分布式知识库的原生支持不足
- 复杂表格、老旧扫描件的解析能力偏弱（这类需求看第 06 篇的 RAGFlow）
- 多 Agent 协作能力有限
- 私有化 ≠ 自动安全：密钥、权限、备份、漏洞修复、成本监控都是你自己的事

## 适合谁、不适合谁

**适合**：有技术团队、要数据自主、需要把知识检索嵌入业务流程的中大型组织；中小团队做知识库原型也快。

**不适合**：纯业务团队零技术资源（看 Coze 或 ima）；文档以复杂表格/扫描件为主（看 RAGFlow）；只需要团队写文档协作（看飞书知识库）。

## 小结

Dify 的位置可以用一句话钉住：**知识库工程化的开源基线**。它的价值不是某个功能独家，而是把「接入-检索-编排-发布」做成了完整、可控、可私有化的标准流水线——你在此基础上长出自己的东西（比如我后来自建 ChromaDB 管线处理 GIS 数据），而不是被它锁死。
