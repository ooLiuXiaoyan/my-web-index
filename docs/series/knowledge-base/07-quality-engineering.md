# 知识库质量工程：垃圾进垃圾出的工程化解法

<span class="badge badge-done">已发布</span>

系列收官篇。前六篇都在讲「选什么平台」，这篇讲一个与平台无关、却决定 80% 效果的话题：**知识库质量怎么做工程化保障**。第 01 篇立过铁律——垃圾进，垃圾出。这篇给它配上工程化解法。

## 第一道工序：切分策略

切分是质量链条的起点，切坏了后面全救不回来。

### 三种切分方式

| 方式 | 做法 | 适合 |
| --- | --- | --- |
| 固定长度 | 按字符数切块 + 重叠 | 通用文档，快速起步 |
| 语义切分 | 按段落/语义边界切 | 长文档、逻辑性强的内容 |
| 模板化切分 | 按文档结构（章节/表格/问答对）切 | 合同、手册、FAQ |

经验参数（来自我 ChromaDB 管线的实践，见 [第 02 篇](./02-my-practice)）：**块 500 字符、重叠 50 字符**，中文文档用这套默认值起步基本不会错，再按检索效果微调。重叠的意义是防止一句话被拦腰切断后两边都失去语义。

### 三个高频坑

1. **表格**：直接切就是灾难——表头与数据分离。解法：先转 Markdown 表格再入库，或用 RAGFlow 这类带表格结构解析的工具
2. **扫描件/图片**：需要 OCR 前置；老旧扫描件识别率低，重要文档建议人工校对一遍再入库
3. **元数据缺失**：每个片段都该带上来源文件、章节、日期——模型分不清片段出处时，回答就会张冠李戴

## 第二道工序：检索质量

检索决定了模型「看到什么」，是幻觉控制的主战场。

### 混合检索是底线

- **向量检索**：擅长语义相近（「怎么赔偿」命中「违约责任」）
- **关键词检索（BM25）**：擅长精确匹配（编号、专有名词、人名）
- **混合检索 + RRF 融合排序**：两路召回各取所长，2026 年已是主流平台的标配（WeKnora、Dify、RAGFlow 都内置）

### Rerank：花小钱办大事

初步召回 Top-20，再用 Rerank 模型（BGE Reranker、Cohere Rerank）精排取 Top-5。多一道重排的成本很低，但能把「相关但不对题」的片段挤出去——检索精度不够时，**先加重排，再调切分，最后才考虑换模型**，这是性价比排序。

### 权限前置

企业场景：检索阶段就要按用户身份过滤可见文档，而不是生成后再遮掩。在索引元数据里写入部门/密级标签，检索时带过滤条件——这是「敏感文档不被不该看的人问出来」的唯一可靠做法（呼应 [桌面助手系列第 07 篇](../desktop-ai/07-security-privacy)）。

## 第三道工序：知识治理

平台上线只是开始，知识库是「养」出来的。

### 生命周期管理

- **入库评审**：不是什么文档都值得进库，过期制度、草稿、重复版本先拦在门外
- **定期清理**：给文档打「有效期」标签，过期自动降权或移出
- **版本管理**：制度类文档保留变更历史，回答时引用现行版本

### 未命中查询复盘

最实用的持续优化机制：**每周分析「用户问了但 AI 答不出」的问题清单**——

- 是知识库里没有？→ 补文档
- 是有但检索不到？→ 调切分/检索参数
- 是检索到但答错了？→ 调提示词或加重排

这个闭环跑起来，知识库准确率会以周为单位肉眼可见地提升。

### 脱敏规范

涉密/敏感场景入库前过一遍清单：人名、地名、坐标、金额、账号。我的安评知识库实践是「典型报告脱敏成模板再入库」——保留结构价值，去掉敏感信息（见 [第 02 篇](./02-my-practice)）。

## 第四道工序：效果评估

「感觉变准了」不算数，要量化：

1. **建评测集**：从真实用户问题里抽 50-100 个，人工标注标准答案与应引用的文档
2. **定期回归**：每次调整切分/检索/提示词后跑一遍评测集，看命中率变化
3. **两项核心指标**：检索命中率（正确文档进没进 Top-K）、引用正确率（回答标注的来源对不对）——前者归检索管，后者归生成管，分开看才知道该修哪头

## 一张总表收束全篇

| 工序 | 关键动作 | 常见翻车 |
| --- | --- | --- |
| 切分 | 500/50 起步、表格转 Markdown、带元数据 | 拦腰切断、表头数据分离 |
| 检索 | 混合检索 + RRF + Rerank、权限前置 | 只用向量、权限后置 |
| 治理 | 有效期、未命中复盘、脱敏清单 | 只进不出、从不复盘 |
| 评估 | 评测集 + 两项指标回归 | 凭感觉调优 |

## 系列总结

七篇走完，从概念到实战到工程：

1. **概念**：知识库的三次跃迁——存储 → 问答 → 执行
2. **实战**：SaaS → 单机 → 私有化 → 自建的四站路线
3. **产品**：ima 的入口、Dify 的工程、Coze 的速度
4. **选型**：按数据敏感度和场景选，不按功能列表选
5. **质量**：切分、检索、治理、评估四道工序

最后留一个判断：**知识库的终局不是更大的库，而是「活的库」**——能自我更新（未命中复盘）、能被 Agent 主动调用（执行阶段）、能在组织间流通（知识广场/MCP）。把四道工序跑成习惯，你的库就已经赢过大多数「建成即荒废」的知识库了。
