# DeepSeek Harness 深度解析：一切皆插件

<span class="badge badge-done">已发布</span> <span class="badge badge-wip">定期刷新</span>

> 📅 信息截至 2026 年 11 月，基于 DataCamp 技术解析与官方文档整理。GitHub：`deepseek-ai/deepseek-harness`，官网：`deepseek.com/harness`，MIT 协议。

2026 年 8 月 13 日，DeepSeek 随 V4 Pro 模型一同发布了 DeepSeek Harness（命令行 `dsh`）。如果说 DeerFlow 的思路是「给你一台装好系统的电脑」，DeepSeek 的思路是另一个极端：**给你一套乐高——连图纸本身都是积木**。

## 核心哲学：Agent = Model + Harness

DeepSeek 把这个等式写进了产品叙事：模型负责推理与生成，Harness 是让推理作用于真实文件系统、并让任务持续推进的一切。两个推论：

1. **模型中立**：Harness 不绑定 DeepSeek 自家模型，DeepSeek、Anthropic、OpenAI 或任何 OpenAI 兼容端点都能接入——换模型不换工具链
2. **Harness 比想象中重要**：它的 Minimal 模式专门用于模型基准测试，因为**测试分数不仅反映模型权重，也反映测试用的 Harness**——这个认知直接戳破了「跑分 = 模型能力」的朴素理解

战略上，这是一次「祛魅」：OpenAI 和 Anthropic 用深度绑定自家模型的 Harness 巩固应用层优势（向下整合）；DeepSeek 选择开源一个模型中立的运行时标准，试图成为 Agent 基础设施（横向铺开）。

## Cordis：一切皆插件

DSH 构建在 Cordis 元框架之上，设计理念源自北大与 DeepSeek 联合提出的**时空可组合性**范式：

- **空间可组合性**：响应式共效应——组件声明自己的依赖，运行时自动协调依赖变化，动态激活与停用
- **时间可组合性**：可逆效应——加载过程即决定卸载过程，组件卸载后的副作用被自动记录并撤销，保证系统长期运行状态一致

落地形态是「**一切皆插件，无特权核心**」：模型适配器、工具注册表、会话存储、沙箱、UI，**甚至驱动 Agent 的主循环本身**——全部是插件。Cordis 内核只做三件事：加载、卸载、依赖解析。插件之间通过稳定的服务键互相发现（`ctx.tools`、`ctx.llm`、`ctx.sessions`），工具调用 `ctx.llm` 时根本不需要知道背后是哪家模型。

配置是分层的：bundles（插件包）→ profile 的 `cordis.patch` → 用户级 patch → 命令行参数，每一层都可以针对具体插件 ID 覆盖配置或插入新插件。`dump config` 命令能打印出整棵启动树，每一行都可改写。

## 四种运行模式

模式 = 不同的插件包组合，回答「这次会话该暴露多少运行时能力」：

| 模式 | 暴露能力 | 用途 |
| --- | --- | --- |
| **Standard** | 文件编辑、Shell、文件/网页搜索、技能、规划、目标、子代理、工作流 | 通用主力，日常仓库工作从这里开始 |
| **PTC**（原 Code 模式） | 工具集与 Standard 几乎相同，但模型改为**编写程序**通过 `run_code` 批量调用工具 | 把多步工具调用压缩成一段程序，权限检查不变 |
| **Minimal** | 只剩持久 Shell + 字符串替换文件编辑器 | 模型基准测试——剥离 Harness 影响，逼近模型裸能力 |
| **Creator** | 可检视运行时、在内存中测试插件 | 开发 preset；甚至可以**在对话中让 Agent 自己写插件、安装并验证** |

注意区分两层概念：**运行时 profile**（web / headless / sdk / sdk-minimal / acp）决定程序如何启动、启动时堆叠哪些插件包；**Agent preset**（上述四种模式）决定会话内能用什么。普通用户跑 `dsh web` 只会碰到后者。

## 会话即事件日志

这是 DSH 最值得借鉴的设计：**会话不是消息数组，而是一条仅追加（append-only）的类型化事件日志**。系统提示、思维链、工具调用、子代理调度、上下文注入，全部序列化为不可变事件。官方文档要求：任何发送给模型的内容，都必须能从这个日志重建。

一份事件流同时支撑了：

- **恢复**（Resume）：中断后接着跑
- **分叉**（Fork）：从任意历史点开一条新支线
- **回放**（Replay）与 **Trajectory 视图**：可视化审计 Agent 的每一步

需要说明：从历史重建上下文 ≠ 确定性重放——模型输出和外部状态可能已经变化，但日志提供了可审计的完整记录。

## 工具执行管线：模型请求 ≠ 直接执行

模型可以按名字请求工具，但无权直接运行。每次调用经过：**策略检查 → 执行 → 结果处理**。模型选择工具，运行时决定是否以及如何执行。

DSH 刻意把两件事分开：**审批**（该不该让用户确认）和**沙箱**（在哪、以什么权限执行）。权限 preset 会把两者打包，但概念上它们正交。

> ⚠️ 一个重要的清醒剂：在系统提示词里写「只许读文件」只是**模型可以遵守的建议**，不是 OS 级沙箱那样的强制边界。安全约束必须落在执行层，不能落在提示词层。（联动 [桌面助手系列第 07 篇](../desktop-ai/07-security-privacy)）

## 安装上手

```bash
# 前置：Node.js（建议 nvm + pnpm）、Git、DeepSeek API Key
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness

export DEEPSEEK_API_KEY=sk-your-key-here   # 或之后在 UI 里配置

pnpm install
pnpm run build
pnpm dsh web   # 启动 Web UI；也可作为桌面应用运行
```

进阶：官方提供 Python SDK，可以用脚本驱动和编排 Agent，适合自动化流水线与既有工作流集成。省钱提示：DeepSeek API 采用峰谷定价，长时任务挑空闲时段跑；配合低价缓存机制，单次任务成本可以压得很低。

## 局限与忠告

- **「一切皆可换」不等于「换起来免费」**：替换模型适配器或 Agent Loop 仍需遵循服务契约写插件，工程投入是真实的
- **插件供应链风险**：加载第三方插件前务必审查——它运行在你的环境里
- **爱惜的仓库请上副本**：在副本或分支上工作，生产凭据不要放进环境

## 小结

DSH 的答案是：**Harness 不该有黑箱**。把运行时拆到「连 Loop 都是插件」的极致，换来的是彻底的可定制与可审计。代价也明显：自由越大，需要的工程能力越强。
