# Harness 设计的关键取舍

<span class="badge badge-done">已发布</span>

系列收官篇。前四篇讲了概念、两个主角和横向对比，这篇沉入水下：**设计一个 Harness 时，那些真正困难的取舍在哪里**。无论你是选型、二次开发，还是准备自己造一个，这四个问题都绕不开。

## 取舍一：状态管理——Agent 的「记忆」怎么存

三种范式，对应三代设计：

| 范式 | 代表 | 优势 | 代价 |
| --- | --- | --- | --- |
| 消息数组 | 早期 Agent 框架 | 简单直觉 | 上下文越滚越大，无法审计、无法分叉 |
| 显式状态机 | LangGraph（DeerFlow） | 流程可控、断点清晰 | 状态 schema 要预先设计 |
| 仅追加事件日志 | DSH | 天然支持恢复/分叉/回放/审计 | 重建上下文有成本，工程复杂度高 |

深层矛盾是个三角：**可恢复性、可审计性、上下文压缩**——三者最多同时满足两个半。事件日志给足了前两者，但长程任务下把全量事件重建为模型上下文太贵，于是仍需压缩策略兜底（DeerFlow 的上下文压缩机制就是干这个的）。

**选型启示**：短任务不用纠结；一旦任务以小时计、或需要审计（金融、法务场景），事件日志范式的价值会指数级放大。

## 取舍二：沙箱与审批——安全与流畅的对冲

执行环境三档：

1. **云端沙箱**：最安全也最疏远——碰不到你的本地环境（ChatGPT 云端方案）
2. **本地沙箱**：Docker/K8s 隔离（DeerFlow 默认）——能干本地活，风险关在容器里
3. **无沙箱直跑**：最快也最危险，全靠审批节点兜底

审批粒度的权衡更微妙：粒度越细越安全，弹窗越多体验越崩。好的设计是**分层默认**（只读放行、写入按范围授权、不可逆操作单次确认，详见 [桌面助手系列第 07 篇](../desktop-ai/07-security-privacy)），外加一条铁律：

> **提示词里的「只许读」是建议，不是边界。** 安全约束必须落在执行层——DSH 把「审批」和「沙箱」设计成两个正交机制，正是这个认知的体现。

## 取舍三：固定核心 vs 无特权核心

- **固定核心**（Claude Code、Codex、DeerFlow）：官方保证核心的稳定与优化方向，体验一致，出了问题有明确的责任主体；代价是核心不合意时只能等官方
- **无特权核心**（DSH）：研究者的天堂，你可以换掉 Loop 验证「换个推理策略会怎样」；代价是兼容性、调试成本全部转移到插件作者身上

插件化有个隐性成本常被低估：**契约设计本身**。插件要解耦，就得先定义稳定的服务契约（DSH 的 `ctx.*` 键、时空可组合性的加载/卸载时序），契约一旦发布就很难改——这本质上是把「内部设计的自由度」换成了「生态协作的可能性」。

**经验法则**：如果你不会写插件，「一切皆插件」对你只是营销词；按你实际会动到哪一层来选。

## 取舍四：内置能力 vs 生态扩展

- **电池全包**（DeerFlow）：编排、沙箱、记忆、技能全内置，第一天就能干活；代价是内置件不合身时替换成本高
- **最小内核 + 生态**（DSH）：内核只做插件调度，能力全靠装；代价是「第一天体验」取决于生态成熟度

在这场取舍里，**MCP 是双方共同的缓冲带**（联动 [MCP 详解](../mcp/01-mcp-detail)）：工具连接这件最易碎片化的工作被协议标准化了，Harness 只需要做好 MCP Host，就能把「连接什么」的问题外包给生态。可以预见，Harness 内置的能力会越来越聚焦在「模型调度与执行约束」，外围能力持续向 MCP 生态迁移。

## 展望：Harness 会走向标准化吗

回看历史，每一层基础设施的终局都是标准化：操作系统、浏览器引擎、容器运行时。Harness 会重演吗？

本系列的判断是：**接口层会（MCP 已经在做），内核层不会**。

- 工具连接、技能格式、会话协议——这些「插口」会标准化，因为生态需要互操作
- 但编排策略、状态模型、Loop 设计——这些「发动机」恰恰是每个框架的存在意义，标准化等于消灭竞争空间

所以更可能的终局是：**少数几个主流 Harness 内核 + 一个繁荣的标准化外围生态**——很像今天「少数浏览器内核 + 统一 Web 标准」的格局。

## 系列总结

五篇回顾：

1. **概念**：Agent = Model + Harness，护城河上移到运行时
2. **DeerFlow**：编排优先，开箱即用的长程 SuperAgent
3. **DSH**：插件优先，连 Loop 都可替换的祛魅之作
4. **对比**：开放派 vs 绑定派，默认配置决定胜负
5. **取舍**：状态、沙箱、核心、生态——没有银弹

最后一个建议送给读者：**别只看 Harness 的发布会，去读它的会话日志格式和权限模型**——一个 Harness 怎么记录历史、怎么约束执行，比它的功能列表更能告诉你它是谁。
